请从零实现一个 Windows 本地不可信 ZIP 接收器，用于把上传压缩包发布为可读取的数据版本。使用 Python 3.12，仅需 CPU，可使用标准库 zipfile 解码，但不能直接调用 extract/extractall。无需网络、Docker、管理员权限或图形界面。重点做好安全路径判定与失败时的原子发布，不需要开发通用文件管理器。

1. 仅接受普通文件和目录，支持 stored、deflate；拒绝加密条目、符号链接及其他特殊类型。ZIP 中的 / 和反斜杠都按路径分隔符处理；拒绝绝对路径、盘符、UNC、冒号、空中间段、. 和 .. 段，以及任一段末尾空格/点、ASCII 控制字符、Windows 非法文件名字符和设备名 CON/PRN/AUX/NUL/COM1-9/LPT1-9（含扩展名、忽略大小写）。本题额外规定按各段 NFC 后 casefold 的结果判断同名，冲突直接拒绝，不自动改名；文件与目录同名、文件充当父目录也必须拒绝。输出保留合法原始名称。不能只靠字符串前缀判断目录归属。
2. 发布根目录由当前用户独占，任务不考察其他进程并发篡改目录；每次解包必须使用根目录下新建的随机空暂存目录，不能向既有版本解包。配置条目数、单文件实际解压字节数及总实际解压字节数上限，边读边限制，不能信任 ZIP 声明的长度，也不能先完全解压再检查。任何路径冲突、超限、CRC 错误、截断或不支持的条目都使整包失败。正常目录条目以及合法零字节文件应被接受；暂存文件和失败版本不能经读取接口可见。
3. 用 manifest.json 记录文件相对路径、实际长度及 SHA256，并通过原子替换 CURRENT 指针发布不可变版本。提供 publish、list、read、verify 命令；每次读取先固定一次 CURRENT，再从同一版本取文件。发布或进程崩溃期间，读者只能得到上一完整版本或新完整版本。发布失败不得改变 CURRENT 或旧版内容；遗留暂存目录可在重启后清理。在写文件中途、manifest 完成后、CURRENT 替换前后设置同步点，强制终止自己启动的发布子进程，并验证重启及读取结果。

自建正常包和攻击性样例，在隔离临时目录中验证目录穿越、大小写/Unicode 冲突、设备名、文件目录冲突、压缩膨胀超限、CRC 错误及四个崩溃位置；根目录外放哨兵文件，验证其字节和目录结构未被改变。测试不需要真的创建符号链接，可通过 ZIP 元数据构造应拒绝的条目。交付工具、自动化测试和 Windows 说明，列出实际通过与未完成项，不得把失败包静默跳过后报告成功。
